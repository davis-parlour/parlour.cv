Selected work.

A few engineering problems I've owned at Palintest.

01 Commercial firmware across four codebasesFeatures, fixes and releases for production instruments. Embedded C · Renesas MCUs

Problem

Four commercial codebases cover established instruments and new product work, so changes need to solve the immediate problem without breaking supported behaviour elsewhere.

Approach

I take changes from requirements or fault investigation through implementation, source-level debugging, physical-instrument testing and release.

Outcome

Features and fixes move from an ambiguous request or failure report to a tested firmware change ready for release.

02 Firmware and hardware fault isolationJTAG, oscilloscope and electrical measurements to isolate faults. JTAG · Oscilloscope · Measure

Problem

Some failures sit between firmware and electronics, where the code alone does not explain what the instrument is doing.

Approach

I make the behaviour reproducible, inspect firmware state over JTAG, vary controlled power conditions and use an oscilloscope or multimeter to compare electrical behaviour with what the software sees.

Outcome

The investigation narrows the fault to the right layer, gives the next engineer useful evidence and lets me validate the final behaviour on real hardware.

03 Hardware compatibility without firmware forksOne firmware path across supported hardware revisions. Compatibility · Legacy support

Problem

The same commercial instrument can contain different supported hardware revisions, while older units still need current firmware.

Approach

I implemented compatibility inside the shared firmware so the correct software path is selected for the installed hardware.

Outcome

Current and legacy hardware remain supported through one maintained firmware path instead of unnecessary product variants.

04 Faster build and debug workflowVS Code, JTAG and Ninja for a shorter change-to-evidence loop. VS Code · JTAG · Ninja

Problem

Slow builds and a fragmented connected-device workflow added friction to routine firmware changes and investigations.

Approach

I moved the workflow into VS Code, integrated JTAG debugging for connected instruments and introduced Ninja for faster builds.

Outcome

Build times fell by approximately 40%, while the integrated debug workflow made it quicker to move from a code change to evidence on the instrument.
